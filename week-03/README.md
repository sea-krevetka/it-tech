### 1. В чем разница между Forward Proxy (обычный прокси) и Reverse Proxy (обратный прокси)?

Forward Proxy все клиенты идут через один прокси, скрывает клиентов от серверов. Используется для обхода блокировок, кэширования, контроля доступа

Reverse Proxy сервера расположены за прокси, скрывает серверы от клиентов. Используется для балансировки, SSL termination, маршрутизации

### 2. Что такое Upstream в терминологии Nginx?
**Upstream** — это блок конфигурации Nginx, который определяет группу бэкенд-серверов, куда прокси будут направляться запросы.

### 3. Зачем скрывать реальные IP-адреса сервисов от клиента?
1. Безопасность: Уменьшается поверхность атаки. Злоумышленник не знает, где физически расположены сервисы
2. Гибкость инфраструктуры: Можно менять IP-адреса сервисов, масштабировать, добавлять новые экземпляры без изменения клиентского кода
3. Централизованная политика доступа: Удобно настраивать firewall, rate limiting, аутентификацию в одном месте
4. SSL/TLS termination: Сертификаты настраиваются только на gateway, внутри сети можно использовать HTTP

### 4. Какие еще задачи, кроме маршрутизации, может выполнять API Gateway (назовите хотя бы 2)?

1. Аутентификация и авторизация: Проверка JWT-токенов, API-ключей перед передачей запроса к сервисам
2. Ограничение запросов: Защита от DDoS-атак и чрезмерного использования ресурсов
3. Трансформация запросов/ответов: Изменение формата данных, агрегация ответов от нескольких сервисов
4. Балансировка нагрузки: Распределение трафика между несколькими экземплярами одного сервиса

### 5. Что произойдет, если Gateway упадет? Как можно от этого защититься?
Все сервисы станут недоступны для клиентов, даже если сами сервисы работают, полный отказ системы. 
1. Репликация Gateway: Запуск нескольких экземпляров Nginx
2. Балансировщик перед Gateway: Использование дополнительного балансировщика (например, HAProxy) перед несколькими gateway
3. Регулярные проверки: Настройка проверок здоровья для автоматического исключения упавших инстансов
4. Резервирование: Запуск gateway на разных физических серверах/зонах доступности
5. Graceful degradation: Реализация fallback-механизмов (например, возврат закэшированных ответов)
