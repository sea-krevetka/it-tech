## Ответы на вопросы для самопроверки (Неделя 6)

### 1. Зачем нужны `variables` в GraphQL запросе? Почему нельзя просто склеивать строки?

Переменные нужны для:
- Безопасности: Предотвращают инъекции (SQL injection аналог)
- Кэширования: Сервер может закэшировать парсинг запроса
- Типизации: Переменные имеют типы, определенные в схеме

Склеивание строк опасно, тк позволяет выполнить произвольный код: (`"1; drop table"`).

### 2. Из каких полей состоит стандартный JSON-запрос к GraphQL серверу?

Стандартный запрос содержит:
- `query` (обязательное) — текст GraphQL запроса
- `variables` (опциональное) — словарь с переменными
- `operationName` (опциональное) — имя операции, если в запросе несколько

### 3. Почему у GraphQL обычно только один URL endpoint?

GraphQL использует один эндпоинт, потому что схема определяет все возможные операции. Клиент сам решает, какие данные запросить через структуру запроса.

Это упрощает:
- Инфраструктуру (один прокси, один балансировщик)
- Мониторинг (все запросы в одном месте)


### 4. Что означает наличие поля errors в ответе сервера? Может ли оно прийти вместе с data?

Поле errors означает, что при выполнении запроса произошли ошибки.
Да, errors может прийти вместе с data (частичный успех). Значит часть запроса выполнилась успешно, а часть нет.


### 5. Как клиент должен обрабатывать ошибки, если HTTP статус ответа 200?

GraphQL всегда возвращает 200, даже при ошибках. Нужно:
1. Проверить наличие поля errors
2. Если есть errors:
   - Вывести их пользователю/лог
   - Если есть data, обработать частично
3. Если только errors (нет data) — запрос полностью провалился
4. Если HTTP статус не 200 — проблема на транспортном уровне


### 6. В чем плюсы использования типизированных клиентов (например, Apollo Client или Relay) перед простыми HTTP-запросами?

Типизированные клиенты дают:
- Type Safety: Проверка типов на этапе компиляции
- Автодополнение: IDE подсказывает поля
- Кэширование: Автоматическое кэширование нормализованных данных
- Оптимистичные обновления: Мгновенное обновление UI до ответа сервера
