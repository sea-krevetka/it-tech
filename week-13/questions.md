### 1. Зачем нужен Helm? Какую проблему он решает?

**Helm** — это пакетный менеджер для Kubernetes. Он решает проблему повторного использования и параметризации Kubernetes манифестов.

**Проблемы без Helm:**
- Нужно копировать YAML файлы для каждого окружения (dev, stage, prod)
- При изменении версии образа нужно править все файлы вручную
- Трудно управлять зависимостями между сервисами
- Нет версионирования и отката установок

**Что дает Helm:**
- Шаблонизация с переменными (вместо жестких значений)
- Возможность создавать один шаблон для всех окружений
- Управление релизами (установка, обновление, откат)
- Зависимости между чартами
- Чарты можно переиспользовать и делиться ими

### 2. Как работает приоритет значений (Values)? Кто победит: `values.yaml` или флаг `--set`?

**Приоритет значений в Helm (от низшего к высшему):**

1. Встроенные значения по умолчанию
2. `values.yaml` (базовый файл чарта)
3. Файлы overrides, переданные через `-f` (последний файл имеет высший приоритет)
4. Флаги `--set` и `--set-string`

**`--set`** имеет наивысший приоритет и переопределяет все остальные значения.

### 3. Что такое функция `include` и `_helpers.tpl`? Зачем они нужны?

**`_helpers.tpl`** — это специальный файл в директории `templates/`, который содержит многократно используемые фрагменты шаблонов.

**`include`** — функция, которая вызывает эти фрагменты и возвращает результат в виде строки.

**Зачем нужны:**

1. **DRY (Don't Repeat Yourself)** — избегаем дублирования кода
2. **Стандартизация** — единый формат меток и имен во всех ресурсах
3. **Сложные вычисления** — например, генерация fullname с truncation
4. **Упрощение шаблонов** — выносим сложную логику в helpers

**Пример:**
```yaml
# _helpers.tpl
{{- define "myapp.labels" -}}
app: {{ .Chart.Name }}
version: {{ .Chart.Version }}
{{- end }}

# deployment.yaml
metadata:
  labels:
    {{- include "myapp.labels" . | nindent 4 }}
```

### 4. Почему в шаблонах Helm так важно следить за отступами и зачем нужна функция `indent` или `nindent`?

**YAML чувствителен к пробелам.** Неправильный отступ делает YAML некорректным.

**Проблема:** Helm шаблонизатор просто вставляет текст без учета форматирования. Вставленный текст может нарушить структуру YAML.

**Решение:** функции `indent` и `nindent`:

| Функция | Что делает |
|---------|------------|
| `indent N` | Добавляет N пробелов в начало каждой строки |
| `nindent N` | Добавляет новую строку + N пробелов |


### 5. Как откатить неудачный релиз с помощью Helm?

**Команды для отката:**

```bash
# Просмотр истории релизов
helm history my-release

# Откат к предыдущей версии
helm rollback my-release

# Откат к конкретной версии (например, к версии 2)
helm rollback my-release 2

# Откат с ожиданием завершения
helm rollback my-release --wait

# Откат с таймаутом
helm rollback my-release --timeout 5m
```


### 6. Можно ли использовать Helm только для генерации YAML, без установки в кластер?

**Да, можно.** Команда `helm template` рендерит шаблоны в YAML без установки в кластер.

```bash
# Базовый рендеринг
helm template my-release ./chart

# С файлом values
helm template my-release ./chart -f values-dev.yaml

# С сетевыми значениями
helm template my-release ./chart --set replicaCount=3

# Сохранить вывод в файл
helm template my-release ./chart > rendered.yaml
```
